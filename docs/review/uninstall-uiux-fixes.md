# 卸载器 UI/UX 评审：修复报告

- 输入：docs/review/uninstall-uiux.md（评审总评 5.3 / 10，4 P0 · 8 P1 · 12 P2 · 6 P3）
- 本次范围：P0 全量、P1 全量、P2 全量、P3 五项；P3-1（整体视觉语言统一）与「撤销卸载」按评审建议留作后续。
- 验证：swift build --disable-sandbox 与 swift test --disable-sandbox（全量用例通过）；另外用离屏 NSHostingView 按真实数据渲染 ready / 扫描 / 删除中 / 完成 / 部分失败 / 系统应用拦截六个状态逐帧核对（见文末截图）。

## 一、结构重组

原 639 行的 UninstallWindow.swift 同时装着模型、窗口控制器与全部视图，无法按层评审与测试。拆成三层（同模块，公开 API 只有新增、无删除）：

| 文件 | 职责 |
| --- | --- |
| Uninstaller/UninstallModel.swift | 状态机、前置体检、扫描编排（两段式）、勾选语义、删除流程、结果报告 |
| Uninstaller/UninstallWindow.swift | 窗口控制器（关闭守卫 / 层级 / 复用）+ 内容视图（头部、主体各阶段、底栏、确认弹窗） |
| Uninstaller/UninstallItemViews.swift | 类目分组、单行条目、抖动图标、FDA 横幅 |

## 二、P0（4/4）

| 条目 | 状态 | 落地 | 行为变化 |
| --- | --- | --- | --- |
| P0-1 删除中可「取消」/可关闭且明细丢失 | 完成 | UninstallModel.performRemoval、UninstallWindowController.windowShouldClose / handleRemovalFinished | removing 阶段底栏只剩进度（无取消）；标题栏关闭/Esc 弹出确认，明确「关闭不会停止删除、失败项只汇总为通知」；若用户仍确认关闭且随后出现失败，窗口会带着逐条明细重新打开，不再只剩 3 秒 toast |
| P0-2 本体移废纸篓不校验返回值 | 完成 | FinderActions.verifiedTrashResult / recycleApp、UninstallModel.performRemoval | recycle 返回 nil/空字典/漏项一律抛 trashRejected 并按失败处理；本体保留在布局里、不清任何关联文件。右键「移到废纸篓」同样受益 |
| P0-3 失败页不回答「应用还在不在」、无后续动作 | 完成 | RemovalReport、UninstallModel.failureGroups / reportText、UninstallWindow.partialFailureContent | 首行固定给出结论（已移到废纸篓 / 仍在原路径），失败项按「没有权限 / 文件被占用 / 受系统保护 / 系统未接收 / 其它」分组；新增「重试失败项」「在访达中显示」「复制详情」 |
| P0-4 运行中的应用被静默强杀 | 完成 | UninstallModel.isAppRunning / waitForTermination、确认弹窗、头部徽标 | 头部显示「正在运行」；确认弹窗明确「会先请求退出，未保存内容可能丢失」，并给出「取消 / 请求退出后卸载 / 强制退出并卸载」三选一；选择「请求退出」而 2 秒内未退出时整单取消，不静默强杀、不删任何文件 |

## 三、P1（8/8）

| 条目 | 状态 | 落地 |
| --- | --- | --- |
| P1-1 没有空间账本 | 完成 | appBundleSize、selectedBytes、plannedTrashBytes、分组小计、头部「应用 512 MB」、底栏「已选 8 项 · 2.26 GB 将移入废纸篓」、完成页「已移入废纸篓 2.1 GB」。表述为「移入废纸篓 / 清倒后才释放空间」，不虚报成「已释放」 |
| P1-2 done/partial 底栏过期计数 + 取消/完成并存 | 完成 | 底栏按阶段整体切换：ready = 计数 + 账本 + 风险摘要 + 取消/主按钮；removing = 进度（无按钮）；done = 摘要 + 在废纸篓中显示 + 完成；partial = 失败摘要 + 复制/重试/完成。计数只在 ready 出现 |
| P1-3 没有后悔药入口 | 完成 | 完成页写明「都在废纸篓里，可随时恢复；清倒后才真正释放空间」，并用回收站返回的真实新位置提供「在废纸篓中显示」。一次性「撤销卸载」未做（评审也标注为后续能力） |
| P1-4 扫描无进度/无取消/同步递归统计大小 | 完成 | 扫描拆两段：先快速路径清单（立即可操作），后台逐项回填大小（行内「计算中…」）；每段扫描有阶段文案（缓存 / 容器 / 自启项 / 个人文件）；「取消扫描」真正中止后台枚举。删除前若体积仍未算完会补算 |
| P1-5 高风险项藏在视口外、窗口不可缩放 | 完成 | 窗口可缩放（720×620 起步，最小 660×560）；内容溢出时滚动条保持可见；底栏常驻风险摘要「另有 4 项高风险未选：2 项个人文件 · 1 项自启项 · 1 项可能相关」+「查看」滚动定位到对应类目 |
| P1-6 分组「全选」会勾选推测项 | 完成 | 分组「全选」只选非推测项；推测项单独一个「全选（含 N 项可能相关）」按钮；确认弹窗把「可能相关」勾选项单独列出 |
| P1-7 行内无法核对内容 | 完成 | 行尾「…」菜单与右键菜单：在访达中显示 / 复制路径；父路径文本可选中复制 |
| P1-8 系统应用仍给「卸载」入口且先清缓存 | 完成 | 新增 UninstallEligibility：/System/ 路径、指向只读系统卷（Cryptex）的符号链接（本机 /Applications/Safari.app 即此类）、只读卷、restricted/immutable 标记一律拦截；入口菜单置灰「无法卸载：系统应用受系统完整性保护（SIP）」，卸载器内显示只读横幅并禁用勾选与移除按钮。删除顺序改为「先移本体，成功后再清关联文件」，本体失败则一项关联文件都不动 |

## 六、测试

新增 Tests/LaunchXTests/UninstallUXFixTests.swift（27 个用例）：

- 回收站返回校验：nil / 空字典 / 部分接收都必须判失败；
- 删除流程：本体失败不动关联文件且保留布局、本体成功才移除布局并统计字节、礼貌退出超时整单取消、用户选择强制退出才强杀、失败项重试、系统应用不进入删除；
- 前置体检：/System 路径、指向 /System 的符号链接、可移除的 Apple App Store 应用；
- 扫描硬化：改名后按 bundleName 命中、父子项去重、两段式扫描（路径无大小 / scan 有大小）、用户文件跳过 .app、类目文案；
- 勾选与账本：分组「全选」不含推测项、账本 = 本体 + 已选之和、风险摘要计数；
- 入口与模型收尾：系统应用无入口、moveToTrash 前置拦截、appDidGetUninstalled 清理选择集。

既有 330 个用例全部保持通过（含 RootViewHostingTests 的 UninstallContentView 挂载冒烟）。

## 七、验收清单对照（评审 §4.6）

- [x] 卸载 SIP 保护应用：界面明确「无法卸载」，不产生任何删除，不显示成功。
- [x] 删除过程中点标题栏关闭：弹确认；取消则继续删除；确认后若出现失败，窗口带明细重新打开。
- [x] 运行中的应用卸载：确认弹窗明确「会先请求退出、未保存内容可能丢失」，并可选择不强制。
- [x] 任意勾选组合下，底部「将移入废纸篓」= 本体 + 已选之和（大小未知时显示「至少」）。
- [x] done 页不再出现「取消」与过期计数；显示实际移入废纸篓的量。
- [x] 从 done 页可一步到废纸篓并选中刚删的项（回收站返回的真实新位置）。
- [x] partialFailure 首行能看出「应用本体是否已移除」。
- [x] Esc / Return / Tab 全流程可用；VoiceOver 能区分各分组「全选」。
- [x] 开启「减弱动态效果」后无持续抖动动画。
- [x] 内容溢出时用户能发现「下面还有风险项」（风险摘要 + 可缩放 + 可见滚动条）。
- [x] 改名后的应用仍能扫到原名对应的缓存/支持目录。
- [x] 卸载完成后 Launchpad 的选择计数、打开态文件夹状态一致（模型层回调收尾）。

## 八、仍待实机确认 / 后续

1. 真实删除链路：回收站行为、SIP/权限失败文案、管理员授权（/Library 自启项）需要真机手动跑一轮；不拿 Safari 试删。
2. 撤销卸载：把废纸篓里对应项移回原位（需要记录原路径与兼容跨卷/同名冲突），评审也标注为可选后续。
3. P3-1 视觉统一：卸载器仍是系统默认卡片风，与主界面玻璃拟态是两套语言；建议单独一轮视觉改版。
4. VoiceOver / 指针交互：无障碍标签已补齐，但逐项朗读顺序、指针命中（P2-12）仍需实机验证。
5. 扫描体积的性能边界：逐项 size(of:) 在条目很多（数百容器）时仍是串行后台计算；实测可接受，若后续成为瓶颈可改成批量/并发限制。
